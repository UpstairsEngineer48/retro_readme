# Retro README

An interactive, Game Boy style developer portfolio that lives inside a GitHub profile README.

The whole device (body, D-pad, buttons, LCD, side panel) is one **SVG image generated by a Python server**. Every button on the device is a link. Pressing one hits the server, the server updates its state, and the next image shows the new screen.

- Live demo: https://retro-readme-three.vercel.app
- Built with: Python, FastAPI, hand-written SVG, JSON-driven content

---

## How it works

```
GitHub README  --(shows image)-->  GET /            returns the current screen as SVG
               --(click button)->  GET /input?btn=A  updates state, redirects back
```

1. `GET /` renders the current state as an SVG and returns it.
2. `GET /input?btn=UP|DOWN|LEFT|RIGHT|A|B` updates the state and redirects.
3. All text content lives in `data/*.json`. Python only draws it.

The status bar at the top of the LCD shows the **current US Eastern time** and a **random battery level**. Both are re-computed on every render.

### Stateless mode

You can render any screen directly, which is handy for testing:

```
/?s=projects&p=1        screen "projects", page 2 (pages start at 0)
/?s=home&m=2            home menu with the 3rd item selected
```

## Project structure

```
retro_readme/
├── server.py                 FastAPI entry point (used by Vercel)
├── main.py                   Local keyboard mode (saves test.svg)
├── vercel.json               Vercel routing
├── requirements.txt
├── data/                     ALL the content, edit these most often
│   ├── home.json             Main menu
│   ├── profile.json          Developer profile
│   ├── skills.json           Skills
│   ├── projects.json         Projects
│   ├── journey.json          Timeline
│   └── contact.json          Contact links
├── assets/
│   ├── fonts/PixelOperator.ttf
│   └── illustrations/*.svg   Pictures shown in the side panel
└── src/
    ├── api.py                Routes: "/" and "/input"
    ├── renderer.py           Builds the full SVG, clock and battery live here
    ├── application.py        Ties state, input and renderer together
    ├── navigator.py          What each button does
    ├── screens.py            Registers the data files as screens
    ├── registry.py           Maps screen "type" to a drawing function
    ├── icons.py              Menu and contact icons
    ├── layout.py             All positions and sizes
    ├── components/           One file per drawn part (menu, projects, skills, ...)
    └── widgets/              Small reusable pieces (card, badge, timeline, ...)
```

## Fork it and make it yours

This project is meant to be forked. Each person runs **their own copy** with their own data, their own Vercel app and their own profile README. Follow these steps in order.

### 1. Fork and clone

Click **Fork** on GitHub, then clone your fork.

### 2. Replace the personal details

These are the only places that contain someone's identity. Change all of them:

| File | What to change |
|---|---|
| `data/profile.json` | Your name, role, education, interests, GitHub handle |
| `data/contact.json` | Your GitHub, LinkedIn, email and website |
| `data/projects.json` | Your projects (delete mine) |
| `data/skills.json` | Your skills |
| `data/journey.json` | Your timeline |
| `data/home.json` | `panel.title` (the device name) and the panel texts |
| `src/components/logo.py` | The device name on the LCD, keep it the same as `home.json` |
| `src/api.py` | `GITHUB_URL`, set it to **your** profile URL |
| `src/config.py` | `BASE_URL`, set it to **your** Vercel URL (see step 4) |
| `README.md` | The demo link and the author line at the bottom |

> **Do not skip `BASE_URL` and `GITHUB_URL`.** Every button drawn on the device links to `BASE_URL`, and `GITHUB_URL` is where visitors are sent back to. If you leave mine in, your buttons will control **my** device and send people to **my** profile.

### 3. Test locally

```bash
pip install -r requirements.txt
uvicorn server:app --reload
```

Open http://127.0.0.1:8000 and click through every screen. If something crashes, see **Common problems** at the bottom.

### 4. Deploy to Vercel

1. Push your fork to GitHub.
2. Import it in Vercel. No build settings needed.
3. Copy the URL Vercel gives you (for example `https://my-retro.vercel.app`).
4. Put that URL in `BASE_URL` in `src/config.py`, then commit and push again.

### 5. Show it on your profile

Your profile README is the repo named exactly like your username (for example `your-username/your-username`). Add the image and the button links from the snippet in **Using it in a GitHub profile README** below, with your own Vercel URL.

### 6. Keep it yours

Anything else you want to add or change is covered in the customization guide further down.

To check a single screen without clicking, use the stateless URLs above.

## Deploying

The repo is set up for **Vercel**:

1. Push to GitHub.
2. Import the repo in Vercel. No build settings are needed, `vercel.json` handles it.
3. Every push to the main branch redeploys automatically.

Whenever the Vercel URL changes, update `BASE_URL` in `src/config.py` and the links in your profile README.

### Using it in a GitHub profile README

Show the image, then add one link per button. Buttons drawn inside the SVG point at your Vercel site (`return_to=vercel`), which works on the demo page but not inside a GitHub README image. So in your profile README, add your own links with `return_to=github`, which send the visitor straight back to your profile:

```markdown
<img src="https://YOUR-APP.vercel.app/" alt="Retro README">

[UP](https://YOUR-APP.vercel.app/input?btn=UP&return_to=github) ·
[DOWN](https://YOUR-APP.vercel.app/input?btn=DOWN&return_to=github) ·
[LEFT](https://YOUR-APP.vercel.app/input?btn=LEFT&return_to=github) ·
[RIGHT](https://YOUR-APP.vercel.app/input?btn=RIGHT&return_to=github) ·
[A](https://YOUR-APP.vercel.app/input?btn=A&return_to=github) ·
[B](https://YOUR-APP.vercel.app/input?btn=B&return_to=github)
```

This is the simplest working version. You can style it with an HTML table or image links.

> The server keeps one shared state for everyone (`live_app` in `src/api.py`), so all visitors see the same screen. GitHub also caches images, so a change can take a moment to show.

# Customization guide: how to add things

Almost everything is a JSON edit. After any change, run the server and open the screen to check it fits.

> **Golden rule:** in every JSON file, `panel.pages` is the text and picture shown in the **side panel**, and it must have **one entry for each page** (for the home menu, one entry for each menu item). If the counts do not match, the screen will crash with an `IndexError`.

### Quick reference

| I want to add... | Edit | Notes |
|---|---|---|
| A project | `data/projects.json` | Max 3 per page |
| A skill | `data/skills.json` | Add to a group's `items` |
| A skill category | `data/skills.json` | New page plus a `panel` entry |
| A timeline milestone | `data/journey.json` | `year` plus `title` |
| A contact link | `data/contact.json` | Pick an existing icon |
| A profile field | `data/profile.json` | `title` plus `subtitle` |
| A whole new screen | JSON plus 4 Python edits | See below |
| A side-panel picture | `assets/illustrations/` | See below |

---

## Add a project

Open `data/projects.json`. Each page holds up to **3 cards**. Add a card to a page's `items`:

```json
{
    "title": "My Project",
    "subtitle": "Short tagline",
    "description": "Tech • Tech • Tech"
}
```

Keep the text short so it fits the screen. As a guide, stay under about 35 characters per line.

**If the page already has 3 cards**, add a new page instead. You need to add two things:

1. A new object in the top-level `pages` list:
   ```json
   { "items": [ { "title": "...", "subtitle": "...", "description": "..." } ] }
   ```
2. A matching object in `panel.pages` (this is the side panel for that page):
   ```json
   {
       "title": "Page Title",
       "description": ["Line one,", "line two,", "line three."],
       "illustration": "projects"
   }
   ```

`description` in the panel is a list of short lines, keep each under about 22 characters.

## Add a skill

Open `data/skills.json` and add the name to the right group:

```json
"items": ["Python", "C++", "Rust"]
```

To add a whole **category**, you need:

1. A new entry in `pages`:
   ```json
   { "groups": [ { "title": "Cloud", "items": ["AWS", "Docker"] } ] }
   ```
2. A matching entry in `panel.pages` with `title`, `description` and `illustration`.

Each skill takes one line and a page fits roughly 7 items. If a category is longer, split it across two pages.

## Add a journey milestone

Open `data/journey.json` and add to `items`:

```json
{ "year": "2027", "title": "Short milestone text" }
```

Keep the title short, and keep milestones in order.

## Add a contact link

Open `data/contact.json` and add to `items`:

```json
{ "icon": "github", "title": "your-handle" }
```

Available icons: `github`, `linkedin`, `mail`, `globe`. To add a new one, add a `case` in `render()` in `src/icons.py`.

## Add a profile field

Open `data/profile.json` and add to `items`:

```json
{ "title": "Location", "subtitle": "India" }
```

## Rename the device

Change the name in **two places** so they match:

- `src/components/logo.py` (title on the LCD)
- `data/home.json` (`panel.title`)

Keep it to about 11 characters or fewer.

## Change the clock or battery

Both are in `src/renderer.py`:

- `US_TIMEZONE` is the timezone name, for example `"America/Los_Angeles"`.
- `random_battery()` controls the battery range. The default is 10 to 100.

## Add a side-panel illustration

1. Put an SVG file in `assets/illustrations/`, for example `cloud.svg`. About the same size as the existing ones works best.
2. Use its file name, without `.svg`, as `"illustration": "cloud"` in any `panel.pages` entry.

Available now: `achievements`, `contact`, `database`, `frameworks`, `journey`, `languages`, `profile`, `programming`, `projects`, `robotics`, `skills`, `tools`.

A missing illustration name does not crash, it just shows nothing.

## Add a brand new screen

Example: an **Achievements** screen.

**1. Create the data file** `data/achievements.json`, copying the shape of an existing one (for example `journey.json`):

```json
{
    "type": "achievements",
    "title": "Achievements",
    "panel": {
        "title": "Achievements",
        "description": ["Awards and", "milestones."],
        "pages": [
            {
                "title": "Highlights",
                "description": ["Things I am", "proud of."],
                "illustration": "achievements"
            }
        ]
    },
    "pages": [
        { "items": [ { "title": "Won something" } ] }
    ]
}
```

**2. Write the component** `src/components/achievements.py`. Copy `contact.py` or `projects.py` and change what it draws. It must expose `render(data,state)` and return an SVG string.

**3. Register the drawing function** in `src/registry.py`:

```python
from .components.achievements import render as render_achievements

RENDERERS = {
    ...
    "achievements": render_achievements,
}
```

**4. Register the screen** in `src/screens.py`, add the file name to `SCREEN_NAMES`:

```python
SCREEN_NAMES = ["home","profile","skills","projects","journey","contact","achievements"]
```

**5. Add it to the menu** in two places:

- `MENU_SCREENS` in `src/navigator.py` (same order as the menu):
  ```python
  MENU_SCREENS = ["profile","skills","projects","journey","contact","achievements"]
  ```
- `data/home.json`: add an item to `pages[0].items` **and** an entry to `panel.pages`, in the same position:
  ```json
  { "title": "Achievements", "icon": "achievements" }
  ```

The menu is drawn at 35 px per row, so keep it to about 6 items to avoid running off the screen.

## Testing a change

1. Run `uvicorn server:app --reload`.
2. Open the screen directly, for example `/?s=projects&p=1`.
3. Check that text does not overflow the LCD or the side panel, and that the page indicator (for example `Projects 2/3`) is right.
4. Press the buttons with `/input?btn=RIGHT` to confirm the pages switch.

## Common problems

| Problem | Cause |
|---|---|
| `IndexError` or a blank screen | `panel.pages` count does not match `pages` count |
| `Unknown screen type` | New screen not added to `src/registry.py` |
| New screen not in the menu | Missing from `MENU_SCREENS` or `data/home.json` |
| Text running off the edge | Line too long, shorten it |
| Time or battery not changing on GitHub | GitHub image cache, wait a moment and hard refresh |
| Wrong time on the deployed site | `tzdata` missing from `requirements.txt` |
